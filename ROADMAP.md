# Roadmap

Implemented local tooling validates repository metadata, maintained source and licences, workflows, development dependencies, documentation and inventory through fixed commands. It does not report or judge fleet health.

The planned Python reference reporter emits only supported compact aggregates under actual source, unit, pack, window, timebase and sequence contracts. A C-friendly specification is not an implemented C port. Raw spike and sensor payloads stay outside this lane.

Future ingest and verify preserve accepted, quarantined, duplicate, conflicting and stale observations. Expected inventory precedes arrivals; coverage includes every required unit/window/sequence slot. Missing or unqualified observations cannot make the fleet healthy or improve an average.

Planned health counters require real epoch/reset/wrap and unit support. Accuracy proxies remain proxies. Timing comparisons preserve signed changes and actual compatible clocks, units, windows and uncertainty. Zero baselines or denominators remain unavailable. Reset-unit compatibility for non-event counters needs source-owner reconciliation.

The intended public operations are ingest, verdicts, recall, export and verify, with reporter and health-feed library interfaces. They are not installed here. Recall reports evidenced units and retained history limits; a partial answer is not all affected units. Health judgment never supplies device-action authority.

Completion requires the whole owned report contract, actual source-qualified reporters, separate public consumers, compact local indexing, full coverage and drift cases, native strict checks, meaningful coverage, documentation and fresh comparison benchmarks. Hosted service, legal compliance, actuation and physical field qualification are not asserted.
